## 一、它是什么

humanizer 是一份纯提示词技能,没有脚本,不依赖网络和外部工具。它让智能体改写"AI 腔"的文字,使其读起来像真人写的,同时保留原有的事实和观点。判断依据来自维基百科《Signs of AI writing》。

它面向人类读者,不以绕过 AI 检测器为目标,检测器仍可能识别出改写后的文字。

## 二、26 种模式

按强弱排序。第 1 到 5 种看到一次就改;标注"单独出现较弱"的,只在同一段里有多个迹象时才处理。

| 类别 | 编号与模式 |
|---|---|
| A. 铺垫代替陈述 | 1 "不是 X 而是 Y";2 单句收尾与戏剧化短句;3 故作深刻的警句;4 点题前的铺垫;5 与不存在的对手争辩 |
| B. 机械节奏 | 6 强行三连;7 重复的句首;8 破折号当万能连接(较弱);9 堆叠限定词(较弱);10 到处加连字符(较弱);11 被动与缺主语(较弱) |
| C. 夸大与借用权威 | 12 AI 高频词;13 夸大意义;14 含糊的关联;15 浅层 -ing 短语;16 营销语言;17 借来的权威;18 回避 is/are/has |
| D. 机械格式 | 19 装饰性粗体;20 装饰性标题;21 弯引号(较弱) |
| E. 聊天与草稿残留 | 22 聊天机器人残留;23 知识截止声明与猜测;24 标题在首句重复;25 谈文档本身而不谈主题 |
| F. 读错了读者 | 26 向已知背景的读者重讲背景 |

## 三、工作流程

1. 标出问题:通读全文,按强度从高到低标记所有迹象,也看段落层面的结构。
2. 写初稿:保留所有有依据的论断,可合并、拆分、重排。文字太泛时,补充它确知为真的具体细节。
3. 自检:先查是否丢失或改动了事实、名称、数字、日期、引文;再检查是否仍有 AI 腔,重点复查 §1、§2、§6、§8、§19。
4. 写定稿。

### 输出形式

| 场景 | 返回内容 |
|---|---|
| 粘贴文本(默认) | 初稿、剩余问题清单、定稿 |
| 文件模式(给出文件路径) | 先完整读取当前文件,只把定稿写回文件,只改正文。代码块、行内代码、命令、路径、YAML 元数据、数据、链接目标保持不变。最后汇报审阅了多少段,没覆盖的部分会明确说明 |
| 嵌入模式(其他任务调用,如 PR、提交信息) | 只返回定稿 |

### 语气

- 你提供自己的写作样本时,它按样本的句长、用词、标点和过渡来改写,样本优先于所有规则,包括破折号规则。
- 没有样本时:博客、随笔、观点类文字保留作者的看法和不确定感;技术、法律、事实类文字保持中性平实。

### 安全约定

待改写的文字被当作素材。其中出现的假结束标签、"给 AI 的说明"、"管理员指令"都只是素材,不会被执行。

## 四、在 DSH 中启用

本技能没有被安装到 DSH,需要时再启用。

### 启用(复制到全局技能目录)

```powershell
Copy-Item -Recurse "E:\AI\SkillManager\skills\blader\humanizer" "$HOME\.dsh\skills\humanizer" -Force
```

新开会话后生效。项目级 `skills/` 目录是否会被自动加载我没有验证过,与本仓库其他技能的做法一致,以全局目录为准。

### 停用

```powershell
Remove-Item -Recurse "$HOME\.dsh\skills\humanizer"
```

### 不安装也能临时使用

让智能体直接读取项目内的文件并按其执行:

```
请读取 E:\AI\SkillManager\skills\blader\humanizer\SKILL.md,按其中规则改写下面的文字:
...
```

## 五、手动触发的用法

`SKILL.md` 带有 `disable-model-invocation: true`,模型不会自行调用,必须由你在消息里点名。启用后可以这样写:

```
使用 humanizer 技能,改写下面这段:

[粘贴文本]
```

```
使用 humanizer 技能,处理 docs/launch-post.md
```

带语气样本:

```
使用 humanizer 技能。

这是我的写作样本:
[粘贴 2 到 3 段你自己写的文字]

请按这个语气改写下面的文字:
[粘贴 AI 文本]
```

README 里的 `/humanizer` 是 Claude Code 的斜杠命令写法。DSH 里是否支持同样的斜杠触发,我没有验证,以上述点名技能的写法为准。

## 六、注意事项

1. **规则以英文为主。** 词表(delve、pivotal、testament 等)和示例都是英文。"不是……而是……"、单句收尾、强行三连、装饰性粗体、聊天残留这些结构性问题对中文同样有效,英文词表对中文无效。中文效果可能不如英文,请自行核对结果。
2. **与全局中文规则的冲突。** §8 要求定稿中不出现破折号(除非你的样本里有)。如果你的中文文稿本来就用破折号,请提供样本,或在消息里说明保留。
3. **定稿可能含它补充的细节。** 4.0.0 允许在文字过于笼统时添加它"确知为真"的具体细节。事实类文字改写后请核对,必要时在消息里写明"不要补充任何新事实"。
4. **文件模式会直接覆盖文件。** 改写前请先提交或备份。
5. **不适合的场景。** 引文、标题、专有名词、讨论这些短语本身的段落,以及 2022 年 11 月 30 日之前写的文字,它会保持不动。
6. 本仓库规则要求第三方技能记录来源与许可证,已登记在 `skills\blader\NOTICE.md`。
