启动一个**后台 agent** 执行调研。它使用全新上下文，在它工作期间，你可以继续做其他事。

它的工作：

1. 针对问题查阅**一手资料**：官方文档、源码、规范、官方 API。二手解读可以作为线索，但每条结论都要追溯到拥有该事实的来源。
2. 把结论写入一个 Markdown 文件，每条结论都注明来源。
3. 保存到仓库已有的笔记目录。遵循现有约定；没有约定时，放在 `docs/research/`，并在报告中写明路径。

## 完成标准

以下条件全部满足，调研才算完成：

- [ ] 每条结论都附有一手来源的链接或路径，没有无来源的结论。
- [ ] 无法访问的来源、互相矛盾的说法，已在文件中单独标明。
- [ ] 结论文件已写入仓库的笔记目录，并向用户报告了完整路径。

## 注意

- 写明版本信息（库或 API 的版本号、查阅日期），因为文档会过时。
- 只摘录与问题相关的结论。
